Getting access to this service

Avian Visitors sits behind a federation gateway. This page explains what that means for you, and which of the three ways in you want.

The short version

You register once, with the federation, and the credential you get works at every service in it — not just this one. The gateway in front of this service checks your credential locally, against keys it has already downloaded. Your request, and the data that comes back, never travel through the federation's central infrastructure.

From a terminal

Use oidc-agent. It is the standard tool across EGI and EOSC, so you may already have it, and it keeps your credential encrypted and hands it out over an agent socket rather than leaving a token sitting in a file.

What it is, and what you actually type

oidc-agent is a package of small command-line tools plus a background daemon, built on the same idea as ssh-agent: the daemon holds your credential in memory, and the tools ask it for tokens. The package is named after the daemon, which is why the commands you type are named after something else. Four names worth separating:

NameWhat it is
oidc-agent The package you install — and the daemon binary inside it, which runs in the background. You rarely invoke this yourself.
oidc-gen Registers an account with a provider. Run once per federation.
oidc-add Loads a registered account into the running daemon. Needed after a reboot, because a daemon that has just started holds nothing.
oidc-token Prints a valid access token. This is the one you use day to day.

Installing it

# macOS — the project publishes its own Homebrew tap
brew tap indigo-dc/oidc-agent
brew trust indigo-dc/oidc-agent      # Homebrew requires this for third-party taps
brew install oidc-agent
brew services start oidc-agent       # runs the daemon, and restarts it at login

# Debian / Ubuntu
sudo apt install oidc-agent

# then check
oidc-gen --version

On macOS the daemon listens on a socket whose path must be in your environment as OIDC_SOCK — see the troubleshooting section below if oidc-token cannot find it.

Registering with this federation




  Registering runs the device flow: it prints a short code and a QR, you open the URL in
  any browser — including on a phone — enter the code and approve. After that the agent
  renews access tokens silently.

Only ever approve a code you started yourself.

  

    The device flow's weak point is that the person approving and the machine
    requesting are not connected in any way the protocol can check. If someone sends

Signing out of a gateway session



  If you have used a /session/ URL, the gateway holds a cookie for you. To
  end it, visit /session/logout. That clears
  the cookie and signs you out of the federation's identity provider as well, returning
  you to the web client.




  It does not sign you out of GitHub. Three sessions exist independently — the gateway's
  cookie, the identity provider's, and GitHub's — so signing out here still leaves the
  next sign-in quick.




Quote your URLs



  If a command fails with zsh: no matches found, the URL never reached
  curl. In zsh — the default shell on macOS — ? is a wildcard,
  and a wildcard matching nothing is an error rather than plain text. An unquoted query
  string is therefore treated as a filename pattern and the command stops before it runs.



curl https://host/api/birds?q=finch      # zsh: no matches found
curl 'https://host/api/birds?q=finch'    # correct



  & is worse and breaks in every shell, not just zsh: it puts the command
  into the background and silently discards the rest of the URL. Single-quote anything
  with a query string and neither can happen.




When oidc-token says "did not receive any response"



  This is not an authentication failure. It means the command could not reach the agent
  holding your credential — usually because OIDC_SOCK is not set in that
  shell. The commonest cause is a terminal window that was already open when the agent
  was first installed: it never inherited the variable.



echo $OIDC_SOCK          # empty? that is the problem
source ~/.zshenv         # or simply open a new terminal



  If it is still empty afterwards, the export is missing. Add it — in
  ~/.zshenv, not ~/.zshrc, because zsh reads
  .zshrc only for interactive shells, so scripts and scheduled jobs would
  never see it:



export OIDC_SOCK="$HOME/Library/Caches/oidc-agent/oidc-agent.sock"



  If OIDC_SOCK is set and the error persists, the agent is not running.
  Start it with brew services start oidc-agent, then reload your account
  with oidc-add <account> — an agent that has just started holds
  nothing.




Quotas



  Requests are counted per credential, per minute, at this service. In this testbed the
  search allowance is deliberately tiny so you can exhaust it in a few seconds and see
  what happens; illustrations get a larger, separate allowance, because one page of
  results pulls several.




  Every response carries X-RateLimit-Limit,
  X-RateLimit-Remaining and X-RateLimit-Reset. Read them
  rather than guessing. When you run out you get a 429 and a
  Reset telling you how many seconds remain in the window.




  Quotas are per service, not federation-wide. A batch job here does not consume your
  allowance somewhere else.




Why the address bar does not just work



  A browser will not put an Authorization header on a request you make by
  typing a URL. That is why there are three routes rather than one: the web client
  attaches the header from JavaScript, the /session/ route replaces the
  header with a cookie the browser will send, and the terminal path does not
  involve a browser at all.




  Some federations offer a ?token= query parameter as a fourth option. This
  one does not, because tokens in query strings end up in server logs, browser history,
  and anything that reads a Referer header.




What the gateway is not doing



  It is not asking the federation whether you are allowed in. It downloaded the
  federation's public signing keys once, caches them, and checks your token's signature
  itself. If the federation's central infrastructure went offline right now, this
  service would keep working until the keys rotate.




  It is also not passing your data through the centre. Bytes go from this machine
  straight to you.
